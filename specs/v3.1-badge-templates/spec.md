# 用途模板与图形 v3.1 规约（造什么）

状态：草案，2026-08-29。方向决策见本文 §1，实现计划见同目录 `plan.md`。

## 1. 定位与方向决策

v3 的内容模型是“一段纯文本加一组全局排版参数”。请假徽章要求逐行字号不同，图标徽章要求画面里出现图形，两者都超出了这个模型。

**这一版走用途模板，不做图层编辑器。** 版式由工具定死，用户只选用途、填内容。判据是实际用法：这些图由团队反复批量生产，版式集中在少数几种，同一批图的观感必须统一。在这个前提下自由排版不是收益而是成本，十个人会排出十个样。模板还锁得住质量下限，也不动渲染管线、序列化与手机端布局。

**失效条件**（出现任一条就要重新审这个决定）：版式种类超过六种；同一种版式里开始出现逐次微调的诉求；使用者从内部同事扩到外部客户，统一观感不再是优势。

## 2. 用户故事

1. 请假前打开页面，选“状态徽章”，首行填“请假中”，次行填“09-01 至 09-05”，导出设成飞书头像。回来改成“已返岗”再导一次。
2. 做部门标识，选“图标徽章”，搜“棕榈”挑一个图标，下面填“产品设计部”，导出 1024 的 PNG。
3. 想要更活泼一点，图标位换成 emoji，中文搜“棕榈”挑中 🌴，同事在 Windows 上打开链接看到的是同一个图形。
4. 把自家产品的 logo 传进来放在图标位，下面配产品名。
5. 前面四种做完，链接发给同事，对方打开就是同一张图，可以照着改。

## 3. 功能规约

### 3.1 用途

三种用途，存在 `config.layout.kind`，默认 `text`。

| kind     | 名称     | 画面构成                       |
| -------- | -------- | ------------------------------ |
| `text`   | 纯文字   | 现状，一段文字按锚点摆放       |
| `status` | 状态徽章 | 首行大字，次行小字，垂直堆叠   |
| `logo`   | 图标徽章 | 图形在上，文字在下             |

切换用途不清空已填的文字。`text` 之外的两种用途仍然共用配色、质感、种子、形状、导出这几组参数，改的只有内容怎么排。

### 3.2 状态徽章

- 内容取 `config.text` 的前两段：第一段是首行，其余段落合并成次行。
- 次行字号等于首行字号乘 `config.layout.scale`，默认 0.42，可调区间 0.2 到 0.8。
- 两块水平居中、垂直堆叠，块间距等于首行字号的 0.18 倍。
- 自动填满对“首行加间距加次行”的整体块做二分，整体块贴合安全框。
- 次行为空时退化成单行，与纯文字用途的观感一致。
- 锚点、对齐、竖排、自动换行这几个控件在这个用途下隐藏：版式已经定死，露出来只会让人改坏。

### 3.3 图标徽章

- 图形在安全框上部，文字在下部。
- 图形占安全框高度的比例是 `config.layout.graphic`，默认 0.52，可调区间 0.3 到 0.8。
- 图形与文字之间留安全框高度的 0.06 倍。
- 文字为空时图形居中，占满安全框的较短边乘 `graphic`。
- 图形按原始宽高比等比缩放，不拉伸。

### 3.4 图形来源

`config.layout.icon` 记来源与标识，三种来源：

| source    | 内容                                                       | 颜色                             |
| --------- | ---------------------------------------------------------- | -------------------------------- |
| `builtin` | lucide 1.37 的 1791 个开源图标，按名字取                    | 跟随文字色，与文字同色同效果     |
| `emoji`   | 一个 emoji，取 Noto Emoji 的单个 SVG                        | 原色                             |
| `upload`  | 用户上传的 SVG、PNG、WebP                                   | 原色                             |

- 内置图标里挑约 160 个常用的，写中英文关键词并按类目分组，在选择器里置顶；其余按英文名搜索。这与字体选择器“精选加全库”的口径一致。
- 上传的 SVG 在写入前消毒：去掉 `script`、`foreignObject`、事件属性与指向外部的引用，只留绘图元素。上传只在本次会话有效，不进分享链接。
- 内置库只收 lucide 与 emoji 两套开源图形，具体产品的 logo 走上传。

**emoji 为什么不走字体。** Google Fonts 确实按 unicode-range 切 Noto Color Emoji，但整套只切 10 片，首片就是 709 KB，用一个 emoji 要拉进来整整一片，是整个应用首屏包的五倍。改成按码点取单个 SVG：`cdn.jsdelivr.net/gh/googlefonts/noto-emoji@v2.047/svg/emoji_u<码点>.svg`，Apache-2.0，一个 1.6 KB 到 15 KB。实测走 fetch 转 Blob 转 `Image` 再 `drawImage` 这条路能正常栅格化，256 见方画出 475 种颜色。文件名规则是码点小写十六进制用下划线连接，变体选择符 `FE0F` 要去掉。版本固定，不用 `@main`。

### 3.5 图形与 emoji 的检索

- 索引来自 `emojibase-data`（MIT）：1949 个 emoji，五种界面语言各有标签与分组，中文查“棕榈树”“热带”都能命中。构建期按语言各生成一份精简索引，选择器打开时按当前语言懒加载。
- emoji 按十个官方分组分栏展示，搜索匹配名称与标签。
- 内置图标按类目分栏，精选那批匹配中英文关键词，全库按英文名匹配。
- 两个选择器共用一套对话框与搜索交互。
- 跨设备一致由 SVG 保证：同一条分享链接在 macOS、Windows、Android 上画出同一个图形。用户直接在文字框里打的 emoji 不在此列，那走系统字体，长相随平台。

### 3.6 界面

- 用途分段控件放在文字面板最上面，三档。
- `status` 用途下文字输入框换成两个：状态、补充。
- `logo` 用途下出现图形选择区：当前图形的缩略图、换图按钮、比例滑杆。
- 图形选择器与 emoji 选择器都走对话框加搜索，复用字体选择器那套 cmdk 交互。手机上是底部抽屉。

### 3.7 配置与兼容

- `config` 新增 `layout` 子树，缺省即纯文字用途。
- URL hash 只编码与默认值不同的字段，已经发出去的链接缺 `layout`，解出来仍是纯文字用途，不失效。
- 上传的图形不进 hash，分享链接里图形来源退回内置或空。

## 4. 非目标

- 不做图层、不做拖拽、不做自由摆位、不做多个图形。
- 不做模板的用户自定义，三种用途写死在代码里。
- 不做批量出图。

## 5. 验收

1. 手机上选状态徽章，两行填完，导出 JPG 不超过 1 MB，无横向滚动。
2. 图标徽章选一个内置图标，图形颜色跟着自动文字色走，深浅配色下都看得清。
3. 图标徽章选一个 emoji，导出的 PNG 在三个平台上图形一致；中文搜“棕榈”能搜到 🌴。
4. 上传一个带 `script` 的 SVG，脚本被剥掉，图形正常画出。
5. v3 时代的分享链接原样打开，仍是纯文字用途。
6. lint、typecheck、单测、e2e 全绿；首屏 JS 不超过 160 KB gzip，图形与 emoji 选择器都在懒加载 chunk 里。
