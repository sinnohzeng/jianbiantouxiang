# 逐行字体与字体名预览 v8.0 规约（造什么）

状态：已封存。与实到实现的差异见文末“实到范围”，现状以常驻文档与代码为准。评审轮的发现与处置见 `docs/audits/2026-09-23-v8.0-plan-review.md`。

## 1. 目标

两件事。

1. 第一行与第二行可以分别设字体与字重。第二行默认跟随第一行，动了第二行的字体或字重才独立。
2. 字体选择器里每个字体名用它自己的字体渲染，一眼看出这个字体长什么样。只看名字，不带样例文字，不在画布上实时预览。

顺带把逐行参数在契约里收成两组。项目在开发期，owner 授权不留兼容：旧存档整体作废，不写迁移。

## 2. 用户故事

- 作为使用者，我给第一行挑了一个粗黑体，第二行想要细一点的宋体。第二行输入框下面就是第二行字体，点开选一个即可，第一行不受影响。
- 作为使用者，我只想让第二行细一点。把第二行的字重下拉改成“常规”，字体还是跟第一行同一款；之后给第一行换字体，第二行跟着换成同一款，仍然是常规体。
- 作为使用者，我想让第二行回到和第一行一样。点第二行字体旁的“跟随”，字体与字重都回到第一行。
- 作为使用者，打开字体选择器往下翻，每一行的字体名就是用那个字体写的，手写体、衬线体、黑体一眼分得开；中文字体有中文名的，写的是中文名。
- 作为使用者，文字卡片上两颗字体按钮上的名字也是用各自的字体写的，和选择器里那一行长得一样。
- 作为使用者，某款字体没加载成功时，我能看出是哪一行、哪一款出了问题。

## 3. 决策与理由

每条都先写反方最强的论证，再写为什么仍这样定。

### D1 契约：逐行参数收成 `line1` 与 `line2` 两组

反方（只加一个字段）：在 `typography` 上加一个 `line2Font`，其余不动。改动面最小，排版、测试与端到端几乎不用碰，这轮的需求只是“第二行能换字体”。

定案：分组。现在的逐行参数散在八个字段里：`fontFamily`、`fontSource`、`fontWeight`、`sizeMode`、`fontSize`、`line2Size`、`lineOffsetsX[]`、`lineOffsetsY[]`，再加第二行字体就是十一个。补偿用数组存，于是要 `LINE_OVERRIDE_MAX` 与 `normalizeNumberArray` 兜长度；第一行为空时第二行晋升主行，`fit.ts` 要按下标 1 去各个数组里取。分组以后每行的字体、字号、补偿在一个对象里，晋升时整组取 `line2` 即可。owner 授权开发期不留兼容，这种一次改清的机会不该用一个补丁字段错过。

```ts
type FontSource = 'google' | 'system' | 'upload'

interface FontChoice {
  family: string
  source: FontSource
  weight: FontWeight // FONT_WEIGHTS 九档之一
}

typography: {
  line1: {
    font: FontChoice
    size: number | null // 画布短边比例 LINE_SIZE_MIN..LINE_SIZE_MAX；null 为自动填满
    offsetX: number // 画布宽比例 ±LINE_OFFSET_MAX
    offsetY: number // 画布高比例 ±LINE_OFFSET_MAX
  }
  line2: {
    font: FontChoice | null // null 跟随第一行
    size: number | null // LINE2_SIZE_MIN..LINE_SIZE_MAX；null 跟随第一行，取其 LINE2_FOLLOW_SCALE
    offsetX: number
    offsetY: number
  }
  padding, lineHeight, letterSpacing, effect, effectStrength, color, pill // 两行共用，不变
}
```

`null` 在两行上是同一个意思：这个值不由用户定，由系统派生。第一行字号的派生者是求解器，第二行字号与字体的派生者是第一行。`sizeMode` 因此并进 `line1.size`，`SIZE_MODES` 删除。

区间与比例收成 `config.ts` 的导出常量：`LINE_SIZE_MIN`（0.04）、`LINE2_SIZE_MIN`（0.02）、`LINE_SIZE_MAX`（0.92）、`LINE_OFFSET_MAX`（0.25）、`LINE2_FOLLOW_SCALE`（0.62）、`LINE_GAP_RATIO`（0.18）、`FONT_WEIGHTS`（100 到 900 九档）。归一、求解器的二分区间与滑杆的上下限都引用它们，一处改动处处生效。

`FontChoice` 只存 family，不存 fontsource id：canvas、css2 与 `document.fonts` 认的都是 family，id、可用字重与版本由目录查找按 family 给出。`-upload` 后缀是上传件在 `document.fonts` 里的命名空间，防止它冒充同名 Google 字体，与 `source` 各管一件事。

归一规则：`normalizeFont` 整份成立或整份作废。family 是字符串且去掉首尾空白后非空、source 在三种来源之内，才算成立；字重四舍五入到整百再夹进 100..900，缺省 400。第一行作废回默认字体，第二行作废即跟随。字段级回落会拼出不存在的组合，例如把来源坏掉的上传件读成一款 Google 字体，加载器白等三档超时。

跟随关系由 `config.ts` 导出的 `lineFont(typography, line)` 一处解释，排版、加载与界面都调它。同一款字体的身份键 `fontKey(font)` 也在这里定义，加载器的缓存、去重与画布的依赖键共用它。

`AvatarConfig` 不带版本号。存档键本身就是版本，见 D2。

行高、字间距、文字效果、颜色、胶囊底仍是两行共用。反方会说字间距也该逐行，但没有人提这个需求，逐行字间距在两行不同字号下的观感也没有定论，这轮不做。

### D2 存档：存档键升 `gradient-avatar:v4`，旧数据作废

反方（静默补默认）：键名不动，`normalizeConfig` 读到没有 `line1` 的旧存档就补默认值，用户至少还留着文字、配色与最近生成。

定案：升键作废。补默认会补出错的东西：默认字体是 Noto Sans SC，韩文界面的老用户读回来就是一款没有谚文的字体，整块掉回系统字体；而升键以后没有存档，`initialConfigSource()` 回到 `default`，`LocaleDefaults` 按界面语言重新接管字体与示例文字，结果是对的。

版本号只留一处：`PERSIST_KEY = 'gradient-avatar:v4'`，存档结构一变就升键，旧键不读也不删。外壳写成 `{ config, history }`，读取只校验 `config` 是对象。原先的 `AvatarConfig.v`、外壳 `v` 与键名三个数各自手写，`config.v` 全仓没有读者，外壳 `v` 在“换结构就升键”之后拦不住任何东西，三处删成一处。

同一轮把另外两个本地键并进 `gradient-avatar:` 前缀：最近使用改为 `gradient-avatar:recent-fonts`，字体目录缓存改为 `gradient-avatar:font-catalog:v1`。目录缓存顺带裁掉 `subsets` 与 `category` 两列：前者只在派生 `cjk` 时用一次，后者唯一的读者 `fontFamilyCss` 本轮删除；实测整份缓存从 267,489 字符降到 140,314 字符，每次冷启动少解析一半。

端到端测试不认识存档键：读配置走 `?probe=1` 探针的 `config()`，落盘走 `flush()`。键名只在 `persist.ts` 定义一次，下次升键不用回头改测试。

### D3 第二行字体：默认跟随，动了就独立

反方（两行各一套完整控件，没有跟随）：模型最简单，两行对称，界面上没有“跟随”这个额外概念。

定案：跟随。多数人不手调参数，两行同一字体是好看的默认；切界面语言时 `LocaleDefaults` 换第一行字体，第二行跟着换，否则切到日文后第二行还停在简体中文字体上。

字号与字体都用 `null` 表达派生，差别只在第一行变化的时候。拖第一行字号时，跟随中的第二行字号先钉在原位：字号是连续拖动，拖的人只想调第一行。换第一行字体时，跟随中的第二行字体一起换：字体是离散换款，多数人把第一行字体当作整张图的字体。两条规则方向相反，是有意为之，界面提示把各自的行为写明。

写入只经 `config.ts` 的三个纯函数，界面组件不手写展开：

- `withLine2Font(typography, next)`：第二行的选择器、字重下拉与在第二行上传都调它。`next` 与第一行字体的 family、source、weight 全相同时写 `null`，否则写 `next`。于是跟随态下点选择器里打勾的那一项、把字重改回第一行那档，都回到跟随，不会造出画面没变、哈希却变了的钉住，撤销栈与历史缩略图也不会多一条看不出区别的记录。
- `withLine1Font(typography, next, weights)`：第一行的选择器、字重下拉、在第一行上传与 `LocaleDefaults` 都调它。第二行钉住、且 family 与 source 和旧的第一行相同时，说明第二行只改过字重，这时第二行随第一行换成新 family，字重取新字体里离原字重最近的一档。第二行钉在别的字体上时不动。
- `FOLLOW_LINE1`：`{ line2: { font: null } }`，“跟随”钮写它。

选择器里点中该行当前那款，只关闭弹层，不写配置。

`LocaleDefaults` 在第二行字体非空时同样放手：动过任意一行的字体，本次会话的字体就不再随界面语言变。

### D4 文字卡片：每行一条字体行，字重改下拉

反方（字重留 chips）：chips 一眼看到全部档位，一次点击，v6 专门把字重从分段控件改成 chips。

定案：下拉。2026-09-23 在 1440×900、zh-CN 下实测：挑选列内容宽 417 px，文字卡片高 622 px，所在列剩 86 px 余量；一套九档字重 chips 一行放得下，占 49 px，两行各一套就多占 2×(49+8)=114 px，超出余量。Figma、Canva、Adobe Express 都是字体名旁边一个字重下拉；字重是低频参数，多一次点击可以接受。

下拉用 shadcn 的 Select（Base UI Select），不用原生 select。原生 select 收起后只能显示选中项的全文，做不到“选项写名字加数值、按钮只写名字”；shadcn 的 native-select 生成件把 `h-8 text-sm` 写死在内层，手机端只有 32 px 高、14 px 字，破了本仓 44 px 触控与 16 px 输入字号的口径，而生成件不许手改；原生弹层用系统样式，紧挨着自绘的字体选择器，同一组控件两种观感。Floating UI 已随顶栏菜单进了首屏，Select 的增量很小。

文字卡片自上而下：第一行输入、第一行字体、第一行字号、第二行输入、第二行字体（第二行有内容才出现）、第二行字号（两行都有内容才出现），往下是文字样式、强度、胶囊三行、文字颜色、折叠组“版面”、折叠组“位置微调”。原来独立的“字体”与“字重”两段删除。字体排在字号之上：改文字多于换字体，换字体多于调字号，字号默认自动、多数人不碰；Figma、Canva、Office 也都是字体名在前、字号在后；自动字号本身由字体决定，先字体后字号读起来顺。估算新卡片高约 636 px，余量约 72 px。

字体行是一行标签加一行控件。

- 标签行：“第一行字体”或“第二行字体”。第二行那条在标签文字后面紧跟“跟随”钮，位置与字号滑杆的“自动”钮一致，两行的钮在竖直方向对齐。
- 控件行：左边字体按钮占满剩余宽度，右边字重下拉定宽。
- 字体按钮上写显示名（见 D6），右侧是与下拉同款的下箭头图标，两颗控件读成一组。第二行跟随时按钮文字用次要前景色，钉住后恢复正常前景色，和开发者工具里继承值显示成灰字是同一个意思。按钮的可访问名同时引用行标签与字体名，读出“第二行字体 站酷快乐体”；`title` 写西文 family。
- 字重下拉：收起态只写名字，选项写“名字”加右侧等宽数字的小号数值，选项文字用界面字体按该档字重渲染，下拉里直接看得到粗细。该字体只有一档时下拉禁用，位置保留，按钮宽度不跳。手机端触发器与选项高 44 px、字号 16 px，桌面 36 px、14 px。
- 加载失败时按钮名字前有一个琥珀色告警图标，读屏读“没加载成功，正用系统字体显示”。换了字体或重新加载成功后消失。

字重名进 i18n，九档五语：简体为极细、特细、细体、常规、中等、半粗、粗体、特粗、超粗；繁体为極細、特細、細體、標準、中等、半粗、粗體、特粗、超粗；英、日、韩用 OpenType 样式名 Thin、ExtraLight、Light、Regular、Medium、SemiBold、Bold、ExtraBold、Black。Figma 在任何界面语言下都显示字体文件里的英文样式名，日韩用户熟悉这套叫法，最长的文案也在 10 个拉丁字母内。

“跟随”钮与字号滑杆的“自动”钮抽成同一个块 `AutoToggle`。

- 文案：第二行字号与第二行字体两颗钮都写“跟随”，五语为跟随、跟隨、Match、連動、연동，都不比现有“自动”的译文长，手机标签列不折行。钮上写的是按下去会发生的事：第一行字号由求解器自动填满，第二行两颗跟随第一行。
- 可访问名带行名全称，如“第二行字号跟随第一行”“第二行字体跟随第一行”，包含可见文字；按下态 `aria-pressed="true"` 并 `aria-disabled="true"`，再点不做事。
- 热区：可见尺寸不变，用伪元素把点击区向上下各扩 11 px，手机端达到 44 px 高。现有“自动”钮实测只有 46×22 px，本轮一并补上。
- 提示：第二行字号的提示里“改为手动”改成“改为独立”，与第二行字体的提示用同一个词。第二行字体的提示写“与第一行同一款字体与字重，第一行换字体时一起换；在这一行换字体或字重即改为独立”。

### D5 字体选择器：锚在按钮上、按行打开

反方（保持居中模态框）：现有 CommandDialog 已经打过两处高度补丁，手机与桌面一套代码。

定案：桌面用 Popover 锚在被点的字体按钮下方，手机用底部抽屉。居中模态框带遮罩与模糊，挑字体时右边的画布整块看不见；Figma、Office、Google Docs 都从触发它的那个框展开，位置本身就说明在改哪一行。手机端与图形选择器一致，用 Drawer，抽屉头写可见标题“第一行字体”或“第二行字体”，为哪一行打开一眼看得出。

每条字体行自带弹层外壳。桌面的 Popover 原语已随顶栏进了首屏，外壳常驻，面板经 Suspense 懒加载，弹层关闭即卸载，第一次打开时才拉面板 chunk，首次加载的占位与列表同高，弹层不跳。手机的抽屉连同面板整块懒加载，沿用导出抽屉的挂载闩：点过一次才挂上，之后常驻，关闭动画完整。cmdk、选择器面板与抽屉都不进首屏入口 chunk。

面板改名 `FontPickerPanel`，必传 `line: 1 | 2`，勾选态看该行生效字体，选中写该行。

- 打开时高亮当前字体：`Command` 的 `defaultValue` 取该行生效字体在列表里第一次出现的那一项，cmdk 挂载时把它滚进视口。现状是默认高亮第一项“Liu Jian Mao Cao”，一打开就回车，那一行就被换成草书。
- 搜索词与上传报错随面板挂载初始化，关掉再开是干净的。
- 触摸打开不弹键盘：Base UI 的弹层在触摸打开时把焦点交给弹层本身，要搜索时点一下输入框。
- 打勾那一项追加一段只给读屏的“当前”，五语为当前、目前、current、使用中、사용 중。

分组自上而下：已上传、最近使用、精选若干组、全部、系统，最后是上传按钮。

- 已上传：列出本会话注册过的上传字体，至多三款，由上传注册表的常驻上限决定。有了逐行字体，给第一行上传的字体要能直接用在第二行，不必再传一遍文件。
- 最近使用：只记 Google 字体。系统字体与上传字体进了表也显示不出来，还占名额。
- 精选：按界面语言排组。简体界面为简、繁、日、韩、拉丁；繁体界面为繁、简、日、韩、拉丁；日文界面为日、拉丁、简、繁、韩；韩文界面为韩、拉丁、简、繁、日；英文界面为拉丁、简、繁、日、韩。繁体组同时收 `tc` 与 `hk` 两类，香港的三款字体原先不在任何精选组里。组内保持 `curated.ts` 的手工顺序，搜索时才按命中强度排。

### D6 字体名的显示

反方（一律西文名）：Google 字体文件的 name 表里只有英文名，原生名得手工维护，owner 只说要看名字。

定案：有原生名的显示原生名。中文字体的西文名只有拉丁字形，“ZCOOL KuaiLe”用站酷快乐体写出来看不出它的样子，预览形同虚设；原生名也是名字，Office 与 MasterGo 都这样显示，Figma 不显示原生名被用户当成 bug 报（调研 §1）。

- 原生名表 `NATIVE_NAMES` 以 family 为键，放在 `curated.ts`，文件头写来源与核对日期。只收作者或发行方渠道能查到的名字，查不到的不收：Noto 系列不写“思源”，那是 Adobe 的品牌；马善政、刘建毛草、龙藏这类坊间叫法不一的也不收。2026-09-23 核实 47 款中日韩精选字体，29 款有原生名，每个原生名都用 css2 `text=` 请求过，字形全覆盖。
- 系统字体一并收录本地化名：PingFang SC 为苹方-简，Microsoft YaHei 为微软雅黑，Hiragino Sans 为ヒラギノ角ゴシック，Apple SD Gothic Neo 为애플 SD 산돌고딕 Neo。系统字体用真 family 渲染，不走网络，显示本地化名没有成本。
- 上传字体显示文件名，去掉 `-upload` 后缀。后缀是工程细节，露给使用者没有意义。
- 唯一入口 `displayName(family, source)`。选择器的行、卡片按钮、预览请求的 `text=`、搜索都调它，同一款字体在任何分组里显示同一串字，预览子集覆盖的字形也就是这一串。
- 原生名不是界面文案，不进五语字典。

选择器的行：

- 有原生名的行：原生名用该字体渲染，后面跟一段界面字体的西文 family 小字；空间不够时先截西文，原生名至多占行宽 65%。
- 没有原生名的行：西文 family 名用该字体渲染，并加 `font-size-adjust: cap-height 0.7`。同是 16 px，Tangerine 九个字母只有 39 px 宽，和 Inter 排在一起像小了一号；按大写字母高对齐后，实测 15 款落在 13.2 到 19.2 px。用 `ex-height` 对齐会把 Monsieur La Doulaise 放大到 48.6 px，不能用。中日韩原生名不加，汉字与谚文不受拉丁度量影响。
- 手写体的笔画会伸出前进宽度，`truncate` 的裁切框左右各多留 4 px。实测 Mea Culpa 左侧伸出 3.5 px。
- 预览就绪前与失败时，名字用界面字体显示；就绪后淡入，行高固定不跳。偏好减少动效时不淡入。
- 原生名那一格标 `lang`（简体 `zh-Hans`、繁体 `zh-Hant`、香港 `zh-HK`、日文 `ja`、韩文 `ko`），西文名标 `lang="en"`。读屏按正确的语言念，就绪前回退到界面字体时汉字也按正确的地区字形显示。
- 行高手机 44 px、桌面 36 px；名字 16 px。
- 名字那一格 `font-synthesis: none` 且字重写 normal，别名 face 不写字重描述符：子集请求的字重是字体自己有的一档，浏览器不会再合成假粗体。

卡片上的字体按钮用同一张预览 face：Google 字体直接请求预览，按钮一直可见，不经可见性判断；就绪前与失败时用界面字体。按钮不用真名渲染：名字里的字多半不在用户文字里，浏览器要按 `unicode-range` 另拉切片：调研实测“马善政楷书”五个字走切片要 250 KB，走子集 3 KB。字重只由右边的下拉表达。系统字体与上传字体用自身 family 渲染。

### D7 预览通道：css2 `text=` 子集，别名注册，只走 Google

反方（构建期预渲染）：构建时把每个字体名渲成 SVG 或雪碧图放在同源，运行时零字体请求，大陆网络下也稳。Canva 的字体列表就是名字图片。

定案：运行时按可见行加载只含字体名字形的子集，以别名注册。预渲染要在构建时下载全部 1972 款字体，产物进仓库或 CDN，而字体目录来自 fontsource 接口，一直在变，预渲染会持续过期；运行时方案每一行 1 到 4 KB，只加载滚进视口的那些行，Google Fonts 官网自己的列表就是这么做的（调研 §2）。

请求：`google.ts` 的 `buildCss2TextUrl(family, weight, text)`，形如 `https://fonts.googleapis.com/css2?family=<family>:wght@<w>&text=<显示名>`。`w` 取该字体离 400 最近的一档，必须显式写进 URL，缺 400 的字体不写字重会 400。每款单独请求，不合并：`text=` 对整个请求共用，合并后每个 face 都要带所有名字的字形，缺字重的字体还会被静默丢掉。2026-09-23 实测（调研 §3）：拉丁字体名 1.0 到 2.4 KB，中文名 1.2 到 3.6 KB；CSS 与字体文件都带 `Access-Control-Allow-Origin: *`；浏览器 UA 下返回 woff2 与精确的 `unicode-range`。

注册：`fetch` CSS 文本，取第一条 `src: url(...)`，`new FontFace(别名, 'url(...)')`，`await face.load()` 成功后 `document.fonts.add(face)`。先 load 再 add，`document.fonts.ready` 不会被预览拖住，首屏画布在等它。别名形如 `fp-<fontsource id>`。不用 `<link>` 注入：css2 返回的 `@font-face` 用的是真名，同名注册一份子集会让 `document.fonts.check` 对没覆盖的字返回 true、`load` resolve 空数组，直接污染加载器的就绪判断（调研 §3 实测）。

调度：每一行在 ref 回调里建自己的 `IntersectionObserver`，root 是这次打开的列表滚动容器，下探半屏；进入视口就请求，请求发出后这一行不再观察。弹层关闭即卸载，重开时是新的列表节点，观察器跟着行一起建、一起销，不会有指向旧节点的 root。每款字体整场会话只请求一次，成功与失败都记住；`fetch` 带 `priority: 'low'`，不与画布字体抢带宽。

不排队，不设并发上限。反方的理由是每注册一个 face 就整份文档重算一次样式，快速滚过 200 行就是 200 次。实测不成立（Playwright 自带 Chromium，4 倍 CPU 降速，200 行别名字体加 2000 个普通节点）：每注册一个就强制 flush 一次，40 次共 219 ms；连续注册 40 个再 flush 一次只要 5 ms；40 次注册分散在 40 个任务里再 flush 是 6.3 ms。样式重算是惰性的，同一帧里的多次注册合并成一次，成本按帧计，与排不排队无关。排队反倒把完成时刻摊到更多帧，还拖慢首屏：打开时视口里有十来行，后面几行要等前面的跑完。

行的就绪态经 `useSyncExternalStore` 订阅预览模块：已加载过的字体第一帧就用别名渲染，再打开选择器、搜索后行重新挂载都不会闪一下界面字体。

失败：这一行留在界面字体，不提示、不重试、不超时，刷新页面才重来。

兜底只到此为止。反方（镜像兜底）：大陆网络下 Google 不可达时预览全灭，主加载器就有 jsDelivr 兜底。定案不兜：一是 jsDelivr 上没有 `text=` 子集，中文字体要按 `unicode-range` 拉整片，显示六个字要 69 到 253 KB，是 Google 子集的 20 到 70 倍，一屏十来款就是几 MB；二是调研实测 fonts.googleapis.com 与 fonts.gstatic.com 在三大运营商 DNS 下都解析到境内节点，GreatFire 2026-09 的观测也是可访问，而 cdn.jsdelivr.net 在 2025 到 2026 年反倒有两段干扰期（调研 §4）；三是预览是装饰，失败的形态就是现在的纯文字名，不比今天差。

预览模块只依赖 `google.ts` 与 `catalog.ts`，与主加载器完全隔离。它很小，随卡片上的字体行进首屏；按可见性请求的那一段只在选择器面板的懒加载 chunk 里。

### D8 字体加载器：按行加载，条目同步查

`loader.ts` 对外只有三个函数：

- `fontJobs(config)`：纯函数，给出“哪款字体要画哪些字”。按 `lineFont` 取有文字的行，同一款字体的两行文字合并；两行都空时给第一行字体配样本。加载与画布的依赖键都由它派生，两处对“要加载哪些字体”的判断同源：第二行钉了另一款字体但还没有文字时不加载它，填上文字后依赖键变化，effect 重跑，把它加载进来。
- `loadFontsForConfig(config, opts)`：对每个 job 并行加载，返回每款一条 `{ font, via, ok }`。`font` 是输入的 `FontChoice`，界面据它的 `source` 选提示文案；`via` 是实际走的通道（google、mirror、system、upload）。画布、导出、长按图与历史缩略图都走它。
- `topUpGlyphs(config)`：给已就绪的字体补上新出现的字，确实补到新字时返回 true，画布据此重绘一次。原先 `PreviewStage` 自己拼字体简写调 `document.fonts.load`，是加载器 `ensureGlyphs` 的简化副本，不记已加载的字，对没加载成功的字体也照样调。

目录条目的查找收成 `catalog.ts` 的同步函数 `findFontEntry(family)`：先查精选清单，再查内存里的目录；内存目录第一次被访问时从本地缓存解析一次，不看有效期，`fetchCatalog` 成功时替换。有效期只决定选择器打开时要不要刷新列表，过期条目的 id、字重与版本照样可用。加载器、字重下拉与卡片按钮都用它，查不到才按 family 猜 id。原先三份查找各有各的顺序：`PreviewStage` 先查精选再 `await fetchCatalog()`，缓存过期时要先等目录接口最多 8 s 才开始拉字体；界面的字重列表只看本会话打开过选择器才有的内存目录，刷新后非精选字体的字重菜单是假的，选了不存在的一档，画面却吸附到另一档。

`nearestWeight` 移到 `config.ts`，与 `FONT_WEIGHTS` 放在一起，`withLine1Font` 要用它；`weightsOf` 移到 `catalog.ts`，与 `findFontEntry` 放在一起。两者只对字重表做计算，没有 I/O，原先放在加载器里只是历史原因。font-family 的字符串工具收成 `src/fonts/family.ts` 一份：`SYSTEM_FALLBACK`、`quoteFamily`（一律加引号）、`fontFamilyStack`、`fontString(font, px)`。排版、加载器、预览与界面都从这里取，依赖方向是 `src/text` 引用 `src/fonts/family`，`src/fonts` 不引用 `src/text`。`loader.ts` 里没人读的 `fontFamilyCss`、`isFontReady`、`readyFamilies`、`SYSTEM_STACK`、`GENERIC_BY_CATEGORY` 删除；`src/fonts/index.ts` 删除，全仓不留桶文件，跨目录直接引用模块。

画布字体失败的提示带上字体名：“站酷快乐体没加载成功，已回落系统字体”，上传字体丢失同理。每款失败字体提示一次，两款都失败时两条提示分得清。store 的 `ui` 记当前回落中的字体键 `fontFallbacks`，字体行据此显示告警图标，见 D4。原先的 `ui.fontStatus` 没有别的读者，改成 `PreviewStage` 的局部状态。

### D9 镜像第二档从 gcore 换 fastly

`MIRROR_HOSTS` 的第二档 `gcore.jsdelivr.net` 在国内三网 DNS 下 CNAME 到与 `cdn.jsdelivr.net` 同一组 Cloudflare 地址，换主机等于没换；`fastly.jsdelivr.net` 走 Fastly，至少在联通线路上是另一张 CDN（调研 §4，DNS 实测加推断）。第二档改成 `fastly.jsdelivr.net`。

### D10 更正过时的 `text=` 结论

`src/fonts/google.ts` 注释、`docs/architecture.md` 字体一节与 ADR-0003 都写着“`text=` 在 Noto CJK 上不生效”。2026-09-23 用浏览器 UA 复测，Noto Sans SC 400 与 700 带六个汉字都只回 2 KB 左右的 woff2，这条结论不再成立。主链路继续不用 `text=`，理由换成真实的那条：文字每改一个字就是一份新子集，CSS 只缓存一天；按 `unicode-range` 切片的静态文件缓存一年，跨文字复用。新写 ADR-0007 记预览通道与这条更正，ADR-0003 状态行注明被 0007 部分修订。`google.ts` 里“Noto Sans SC 单片约 2 KB”也不准，常用字的切片是 24 到 43 KB，一并改掉。

### D11 持久化校验继续手写

反方（换 schema 库与 zustand `persist`）：2026 年常见的本地持久化组合是 zustand `persist` 的 `version` 加 `migrate`，读档时用 Zod 4 或 Valibot 做 `safeParse`。

定案：不换。`normalizeConfig` 既给每次写入夹值，又给读档兜底，语义是越界夹回、坏字段回默认、永不抛错。两家库的基本形态是校验失败时报错，要做到同样的语义得在每个叶子上挂 `.catch()` 或 `fallback()`，夹值还得再接 `transform`，写出来不比现在短，而 `AvatarConfig` 接口加返回类型已经保证了字段完整。`persist` 中间件的 `version` 与 `migrate` 为迁移而设计，本仓不迁移；300 ms 防抖、导出前的同步落盘与缩略图裁剪都要自定义 storage 才放得进去。手写版真正的短板是区间散在多处，D1 用导出常量收口。

## 4. 不做

- 不带样例文字，不用用户自己的文字做预览，不在画布上悬停或键盘高亮时实时预览。owner 明确只要看字体名。
- 不做逐行字间距、逐行文字效果与逐行颜色。
- 不迁移旧存档。
- 不做构建期预渲染，理由见 D7。
- 预览不走 jsDelivr 兜底、不超时、不重试、不合并请求、不排队，理由见 D7。
- 不上虚拟列表。“全部”分组仍最多渲染 200 行，靠搜索收窄：cmdk 官方写明 2000 到 3000 项内性能良好，方向键导航靠 DOM 查询，套 `@tanstack/react-virtual` 要绕开它自己的导航（调研 §5）。
- 不加按书写系统或分类的筛选。精选清单已经按书写系统分组并随界面语言排序，全库靠搜索。

## 5. 验收

- 默认配置下两行同一字体；改第二行字重后 `line2.font` 是第一行那款加新字重；点“跟随”回到 `null`。
- 第二行跟随时，在第二行选择器里点打勾的那一项，`line2.font` 仍为 `null`，撤销栈长度不变。
- 第二行只改过字重时给第一行换字体，第二行跟着换成同一款，字重取新字体里离原字重最近的一档；第二行钉在另一款字体上时给第一行换字体，第二行不变。
- 第二行跟随时给第一行选新字体，画布第二行同步换字体，`line2.font` 与 `line2.size` 仍为 `null`。
- 第二行钉住后切换界面语言，两行的字体都不变。
- 第二行换字体后，第一行的 `font` 与 `line1.size` 不变；手动档下第一行的字号像素不变；自动档允许求解器按新的行宽重新求解，两行仍整体居中。
- 第一行为空、第二行有内容时，第二行用自己的生效字体与补偿居中。
- 第二行钉了另一款字体、文字为空时刷新页面，再在第二行输入文字，那款字体被加载，画布第二行不是回退字形。
- 导出与画布一致：所有 job 的字体都就绪才出图。
- 选择器打开后，滚进视口的行在网络可达时换成自己的字体；关掉再打开，照样换；画布同名字体的渲染不受预览影响。
- 桌面上字体选择器贴在被点的按钮下方，画布没有遮罩；手机上抽屉头写着为哪一行选。
- 打开选择器时高亮的是该行当前字体；关掉再打开，搜索框为空。
- 刷新后非精选字体的字重下拉只列这款字体真实具备的档位。
- 1440×900 桌面首屏四张卡片底边在视口内，两个挑选子列不溢出；手机端字体行控件与“跟随”钮的触控高度不低于 44 px。
- cmdk、选择器面板与手机抽屉不进首屏入口 chunk。
- 闸门五步全绿，e2e 两档全绿。
