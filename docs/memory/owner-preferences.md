## 开发阶段授权

项目始终处于开发阶段：不做兼容层、不留旧路径，可以大刀阔斧改。这条授权没有到期日，
除非 owner 另行收回。

## 范围收敛：半成品不进主干

完成一个最小闭环就停，不为“以后会用到”预留还画不出东西的能力；判据是“半成品不进主干”，
不是“这一片做不动”。要继续做就整段推迟到下一轮规约，不留一半在主干里。

## 炫技高于维护性红线

这个项目除了日常使用也是秀肌肉的作品，炫技需求的优先级高于首屏预算、不引入重型渲染库这类
维护性红线，所有红线都可以迭代放宽。体积、文件大小、手机首开速度不是考虑项，慢就用加载动画
兜底。涉及动效与视觉特效，先在 React Bits Pro / starter 与 shadcnblocks 里找现成件，找到就用，
不自建替代品，依赖大小不是否决理由。

## 预览类需求只做最小形态

owner 要“字体预览”时明说只看字体名在该字体下的样子：不带样例文字，不做画布悬停预览，不做方向键实时预览，
“没必要动态预览，太费劲了”（2026-09-23，v8.0）。同类需求默认先做能一眼看出差别的最小形态，
更重的交互等 owner 自己提。

## 典型用法：多数人不手调参数

同事的典型操作路径是改文字、可能加图标、随机刷配色挑一张好看的，只有极少数人会调补偿这类
细参数。默认配方因此必须自己足够好看，边距、字号这类默认值以“大多数人不会碰它”为前提去定。

## 无人值守整轮推进

owner 会把一整轮需求（含要自己拍板的交互决策）一次说完，先要一个阻塞他的答案（比如某个控制台怎么填），
然后离开，让 Claude 无人值守做完：规约与计划落盘、分片实现、闸门与 e2e、分批 commit、最后 push。
交互细节不要回头问他，用双向钢人把正反两边都写透再自己定，理由进规约；他回来看的是仓库里的 Markdown，
所以给他看的东西（部署 SOP、决策依据）写进 `docs/` 或 `specs/`，不只留在对话里。
并发子智能体不超过 5 路、最高 Opus 5，避免一轮把周额度烧光。

## 注释、提交信息与常驻文档只写现状

owner 把“番茄炒蛋（无东坡肉）”当成事故：一个东西被砍掉或从来没加，注释、README、commit message
里不要再出现“不再有 X”“这里没有 Y”“为什么不需要 Z”这类句子，测试里也不要专门断言已删功能不存在。
现状写成肯定句，砍掉了什么与为什么砍进 CHANGELOG 与规约的“实到范围”。这是对全局约定
“常驻文档只写现状”的加严，覆盖代码注释与测试。
