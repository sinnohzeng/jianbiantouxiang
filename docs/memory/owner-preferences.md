## 工作方式

用户授权单人项目直接在 main 工作，验证后提交、打标签、推送，不开 PR。整轮任务按 SDD 推进，具体选择可自主决定；每轮交付列出文档、长期记忆与文档债务，以及实际验证范围。

用户允许重构，不要求保留过时设计。已明确保存的配置按当前兼容要求保留；不要把早期“大刀阔斧”的授权解释成可以删除用户数据。功能应完成可用闭环，不为尚未需要的能力增加结构。

项目也是视觉作品，用户曾允许为明确的演示目标放宽体积预算；日常编辑仍应服从当前提出的可读性、空间和操作要求。动效组件优先参考已授权 registry。核查类智能体每轮最多 5 个。

## 写作（2026-11-14）

用户要求先读所提供的《怎样写作》与写作技能，再写项目文档。先确定立场、受众、目的和提纲，依次审查事实、结构、句词。去 AI 味不等于口语化，清楚的书面语可以。

README 面向新用户，主线是用途、开始使用、进阶入口。技术机制、开发与经验分别归位，同一事实只详述一次。删除无关设计后，不在正文和提交里继续强调“没有加什么”。原书与附带技能是私人参考，只将原创方法写入仓库。

## 视觉与操作

用户主要用于群聊头像：大部分人只改文字、选 Logo、换配色，因此默认效果要直接可用。用户认可中文主行衬线、副行无衬线的小字组合，偏好深色背景和白色品牌文字；后续放大应保留已认可的内部比例与间距。

用户要求头像文字默认有适度投影，方便浅背景辨认；这是头像画面要求，不是网页 UI 字体要求。

手机常调两行文字和 Logo 的大小、上下位置；字体低频，适合收起。偏好平铺的编辑区、明确数值与加减微调。客户 Logo 是高频入口，应方便触达。

字体预览优先显示字体名本身，不为预览另加复杂交互。关于页入口放设置，在新标签打开以保留编辑状态。

## 研究与验收

项目研究采用至少 OKF v0.2 的可追溯 Markdown，先核实规范。研究结论须说明适用范围，不能为追随论文增加无关功能。视觉判断依赖真实素材、实际小尺寸与用户参照，工程指标和审美认可分别报告。
