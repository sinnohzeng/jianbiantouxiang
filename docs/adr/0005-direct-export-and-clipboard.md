# ADR-0005 导出入口：直接下载与显式复制图片

- 状态：已采纳
- 日期：2026-08-29
- 关系：取代 ADR-0004 中“移动端优先 Web Share”的入口决策；编码与体积二分仍沿用 ADR-0004。

## 背景

默认头像导出的用户预期是“点导出，文件落下来”。原来的路径是先打开导出抽屉，再点一次导出，随后在支持的浏览器里进入系统分享面板；对只想换头像的用户多了两层决策。另一个高频诉求是把图直接粘贴进聊天窗口，这需要图片剪贴板，而不是复制配置链接。

## 决策

- 底栏与面板底部的主“导出”按钮直接合成当前图并触发 `<a download>` 下载。
- 主按钮旁保留一个显式设置图标，用于打开导出抽屉调整格式、体积与底色。
- 导出抽屉动作区固定为两个按钮：下载、复制图片。复制图片固定编码为 PNG。
- 复制图片时把 `Promise<Blob>` 同步交给 `ClipboardItem`，再调用 `navigator.clipboard.write`，满足 Safari 对用户手势的约束。
- 不支持图片剪贴板或权限被拒时给出明确失败提示，不静默降级为复制链接。
- 微信内置浏览器会拦截下载，仍打开导出抽屉并展示长按保存预览。

## 后果

- 用户少一次点击即可得到文件；需要分享到系统面板的用户可先下载，或未来再增加显式“分享”入口。
- 剪贴板使用 PNG，体积通常大于 JPG；这是粘贴兼容性的代价，不影响用户选择的下载格式。
- Safari 上合成耗时不会破坏手势，但写入仍可能因权限或策略失败，因此必须有显式错误状态。
