# ADR-0007 字体名预览：css2 `text=` 子集以别名注册，只走 Google

- 状态：已采纳
- 日期：2026-09-23
- 修订：ADR-0003 里“不用 css2 的 `text=` 参数”一条的理由

## 背景

字体选择器原先只列字体名，看不出字形。owner 要求每个字体名用它自己的字体渲染，不带样例文字，不在画布上实时预览。选择器最多同时渲染两百多行，每行一款字体，要在大陆网络下可用，而且不能影响画布字体的加载与就绪判断。

## 决策

- 每款字体单独请求 `fonts.googleapis.com/css2?family=<family>:wght@<w>&text=<显示名>`，只拿显示名那几个字的子集，拉丁名 1.0 到 2.4 KB，中文名 1.2 到 3.6 KB。`w` 取该字体离 400 最近的一档并显式写进 URL，缺 400 的字体不写字重会返回 400。
- 取 CSS 文本里第一条 `src: url(...)`，用 `new FontFace('fp-<fontsource id>', 'url(...)')` 以别名注册，先 `load()` 成功再 `document.fonts.add()`。
- 每一行在 ref 回调里建自己的 `IntersectionObserver`，root 是这次打开的列表滚动容器，下探半屏；进入视口就请求。每款字体整场会话只请求一次，成功与失败都记住；`fetch` 带 `priority: 'low'`。
- 失败的行留在界面字体，不提示、不超时、不重试。
- 中日韩字体有作者或发行方给出的原生名时，显示并请求原生名；原生名表以 family 为键，手工维护。

## 后果

- 画布字体的就绪判断不受预览影响：别名与真名互不相干。
- 预览只依赖 Google 可达。Google 字体两组域名在国内三网 DNS 下解析到境内节点（2026-09 实测），不可达时选择器退回纯文字名，与预览上线前一样。
- 原生名表随精选清单一起偶尔核对。

## 否决的备选

- 用 `<link>` 注入 css2 样式表：返回的 `@font-face` 用真名，同名注册一份子集会让 `document.fonts.check` 对子集没覆盖的字返回 true、`load()` resolve 空数组，画布的就绪判断被污染。
- 构建期把字体名预渲染成图片：要在构建时下载全部约两千款字体，产物进仓库或 CDN，而字体目录一直在变，预渲染会持续过期。
- 预览走 jsDelivr 兜底：jsDelivr 上的 fontsource 没有 `text=` 子集，中文字体按 `unicode-range` 拉整片，六个字要 69 到 253 KB，是 Google 子集的 20 到 70 倍。
- 排队与并发上限：理由是每注册一个 face 就整份文档重算一次样式。实测样式重算按帧合并，同一帧里注册多少个都只算一次，排队只会把完成时刻摊到更多帧。

## 对 ADR-0003 的修订

ADR-0003 写着“不用 css2 的 `text=` 参数：2026-08-29 实测 Noto Sans SC 700 传 `text=` 仍返回 4.6 MB 的 woff2”。2026-09-23 用浏览器 UA 复测，同一请求只回 2 KB 左右的 woff2，这条理由不成立，推断旧结果来自非浏览器 UA。主链路仍不用 `text=`，理由换成：文字每改一个字就是一份新子集，CSS 只缓存一天；按 `unicode-range` 切片的静态文件缓存一年，跨文字复用。
