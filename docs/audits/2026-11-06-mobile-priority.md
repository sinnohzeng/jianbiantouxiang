# 手机高频排版操作复核

## 原始界面与决策

以 iPhone 15 393×659 CSS px 实际页面检查：原第一行字号数字框位于 y≈492，第一行输入 y≈342，其间是字体与字重；上下位置位于末尾折叠区。用户高频操作与界面顺序不匹配。

保留单棵控件树与现有 sticky 预览，将字号及上下位置放到对应文字旁，Logo 大小和上下位置常显；字体、样式及低频版面折叠。恢复自动入口只恢复两行自动字号、图文位移及选中品牌默认图形比例，文字、字体、颜色和 Logo 选择保留。

新第一行字号数字框 y≈414，提前约 78 CSS px；输入因标题栏恢复入口增高约 20 px。第二行输入位置不因此提前：上下控制常显占据空间，这是优先高频操作的明确取舍，不声称所有内容同时进入首屏。低频字体不会挡在字号前。真实手机键盘和 Safari 浏览器仍需设备验证，当前为 Chromium 移动视口及触控模拟。

## 验证与反证

默认折叠、常显上下移动、恢复自动保留内容的单测已加入；五语 key 清单同步。843 单元测试通过（含保存图即时失效回归）。最终 E2E、设备截图、实际触控记录和发布状态由交付结果给出。

首次开发态截图中覆盖图片暂未显示文字，实际文字画布和原始长按 JPG 均有完整文字。等待图片 decode 后截图恢复正常；没有为截图时序误改产品绘制逻辑。设备批量截图与 E2E 同时执行时出现 30 秒截图超时，需要在低负载下重新生成，不能将不完整截图计作通过。

## 实际预览修复

另行操作发现真实问题：旧的长按 JPG 在新配置编码前盖住实时画布；现仅显示与当前配置同一快照的图片，配置变化立即撤下旧图。编码失败继续展示实时画布，不让用户误存旧状态。用 hook 测试覆盖成功、配置变化与失败，再由移动 E2E 验证旧图移除及新图出现。

iPhone SE 出现小字号提示时，原固定 40 px 提示区预算不足，整组预览垂直居中导致头像顶部被 sticky 区裁掉。改为 ResizeObserver 实测提示区高度，从可用高度扣除提示与间隔，保留完整头像。该调整只影响编辑器预览尺寸，不改变导出构图。移动 E2E 增加画框必须完整位于预览区的边界断言。

桌面字体弹层在入口下移后会按剩余空间向上展开；原测试仅允许向下是旧位置假设。断言改为贴近锚点、上下任一方向且完整处于视口，保留无遮罩、字体字重和跟随操作验证。iPhone 15 与 iPhone SE 实际触控均完成两行大小/上下、Logo 大小/上下及恢复自动，未发生横向溢出；完整头像与提示均已目检。

另一条旧宋体测试遗漏了展开字体区，且旧测试把副行设为与新默认主行完全相同的宋体 700，按既有契约会合并为 null 跟随。回归改为先把主行设成黑体，再测试独立副行宋体 600→700 和刷新保留；未修改产品的跟随语义。

发布前最终验证：843 单测及静态/构建门禁通过；完整 E2E 49 项通过，2 条旧 UI 假设修正后分别通过，合计覆盖 51 项。未修改实际产品的字体跟随契约或放宽圆裁校验。

设备批量截图最终采用系统 Chromium、每个设备/主题启动独立浏览器，16 张生成完成；默认 Playwright 浏览器复用实例的截图超时未被当作产品通过证据。页面操作门禁仍由 CI 同版 Chromium 156 执行。英语截图中云环境无法直连第三方字体时出现 Inter 回退提示；中文客户样例使用本站字体已验证。

截图目检还发现脚本的“导出抽屉”动作仍点主下载按钮，文件虽命名 export 实际没有展开抽屉；现改为 export-options 并等待抽屉控件可见，按中文界面重新生成。此为截图工具修正，真实导出与复制流程已由 E2E 验证。
