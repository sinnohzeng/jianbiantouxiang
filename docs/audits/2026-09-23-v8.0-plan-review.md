# v8.0 规约与计划评审处置

日期：2026-09-23。对象是 `specs/v8.0-line-fonts-and-preview/` 的第一版规约与计划。本报告只记当轮发现与去向，不记现状；现状以定稿后的规约、计划与常驻文档为准。

## 1. 方法

四路 Opus 评审各持一个视角并行读规约、计划、调研与相关源码，另有一路 Sonnet 核实精选中日韩字体的原生名，合计五个智能体。四个视角是用户体验、前端工程、软件架构、数据与契约（本仓没有数据库，这一路看存档、目录缓存与归一化）。评审要求对照 2026 年年中的行业做法找差距，同时点名过度工程与过度兜底；每条发现带位置、问题与改法，能实测的给实测数。

四路共报 65 条，去重合并后 45 项。全部在定稿的规约与计划里有去向：采纳 38 项，改写后采纳 5 项，否决 2 项。没有留到下一轮的项。

## 2. 发现与处置

“视角”一列：体验、工程、架构、数据。同一问题被几路同时报出的，合在一行，视角并列。

## 3. 取舍原则

- 过度工程：凡是只为 jsdom 存在的运行时分支、只为防一个不成立的性能假设造的调度件、没有读者的字段与导出，一律删；测试环境缺什么在测试里补。
- 过度兜底：预览失败就是今天的纯文字名，不超时、不重试、不走镜像；存档结构一变就升键，不写迁移。
- 顶层设计：跟随语义、加载任务、目录查找、字体字符串各收成一个出处，界面与测试都只调它。
