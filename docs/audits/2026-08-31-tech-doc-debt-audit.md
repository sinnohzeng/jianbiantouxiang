# 技术与文档债务审计报告

日期：2026-08-31。读者是接手本仓库迭代的开发会话与代理；我是本轮审计者，权限为全仓只读加实测。
每条结论带证据与落地去向，能在仓库里复核，不接受“应该有”式的判断。

## 1. 方法与范围

逐文件读完 `src/` 全部源文件、`specs/` 五组规约与计划、`docs/` 全部说明文档、`tests/` 47 个
单测文件、`e2e/` 四个用例文件、CI 与构建配置，并实跑验证：

- `npm run lint`、`npm run typecheck`、`npm test`、`npm run build` 于本轮审计中段（工作区干净时）
  全绿，单测 627 条，e2e 12 条（桌面 6、手机 4、冒烟 2）。
- 首屏 JS 按 `docs/architecture.md` 的口径实测：entry 154.16 KB gzip，加 modulepreload 三件
  （preload-helper 11.05、i18n 16.70、useScrollLock 22.18），合计 204.09 KB gzip。
- README 样张逐张目检，颗粒列与默认值标注与现行代码比对。
- git 标签、CHANGELOG、`package.json` 三者互核。

审计进行到后半段，另一个会话把 v3.2 图标徽章的规约、计划与半成品代码写进了工作区
（`specs/v3.2-icon-badge/`、`src/graphics/`、`docs/handoff/`）。v3.2 的规约与计划因此纳入
本轮评审，见 §4；当前工作区的 typecheck 红来自该会话未生成的索引产物，不是本仓主干债务，
接手者不要把它当审计发现修。

本报告只记本轮发现与落地去向，不记现状；现状以 README 与 architecture 为准。

## 2. 总体判断

这是一个工程纪律高于平均水平的纯前端项目：契约单一、归一化兜底到处、预览与导出共用管线、
懒加载有挂载闩、测试按消费端断言。债务不在主干代码，集中在三处：发布卫生（标签、版本、
安全文档）、文档与样张漂移、少量“导出却无人读”的契约重复；体验层有两个真实缺口：撤销与
历史缩略图；其余是工程守卫、供应链与文档类别项，见清单逐行。二十二项发现全部落在 `specs/v3.1.3-debt-and-hygiene/` 的六个切片里、旧规约的
评审修订里，或已在审计当轮修掉，没有遗留 TODO。

## 4. v3.2 规约与计划评审

v3.2 的规约与计划整体合格：图形来源三路的许可证、版本钉选（lucide 1.37、emojibase 15.0.0、
Noto Emoji v2.047）、白名单消毒、懒加载口径都对，调研文档带来源与实测口径，是好的先例。
问题四条，已在文档内修订：

1. 预算数字照抄作废的 160 KB（F17），改成 250 KB 加预算脚本守卫。
2. `layout.scale` 没有移除时点（F18），改成随本版 `logo` 一起删，迁移留在 normalize。
3. 缺消费端断言（F19），风险节补“删掉图形落笔调用就有测试变红”的硬要求。
4. 与 v3.1.3 的写域重叠无合并约定（F20），风险节补 v3.1.3 先合、合前 rebase。

另有一件不在规约里：并行会话已写出的 `src/graphics/` 还缺 `generated/` 索引产物，
typecheck 红。这是切片纪律问题（生成脚本与产物应同切片提交），由该会话自己收尾，
本报告不重复立项。

## 5. 考虑过但不算债务

这一节防止下一轮对话把权衡当债重开，也防止把排除项当遗漏：

- 导出体积二分在全分辨率画布上做：实测 4096 最坏约 3.3 秒，在预算内，不换缩图代理。
  既有权衡，见 engineering-lessons“评审收尾”。
- 8192 加 1 MB 的降级路径只有单测没有 e2e：软件渲染下一次 8192 合成要几分钟。既有权衡。
- 像素级视觉回归：headless swiftshader 出图不稳定，像素对比制造假红。维持截图加目检，
  样张脚本（切片二）给目检稳定输入。
- css2 主链不加 SRI：返回内容随 UA 变化，完整性哈希不可行；页面也不注入第三方脚本。
- PWA 不加 navigateFallback：单页 hash 路由，`/` 在预缓存里，没有深路径。已查 `dist/sw.js` 确认。
- `isRecord`、`clamp` 等小助手在各模块重复：模块自包含是本仓明确风格，集中反而扩大公开面。
- useScrollLock 的 22.18 KB 在首屏：BottomBar 的下拉菜单是首屏件，预算内不动它；
  超预算时由切片三的守卫脚本报警再处理，不预支优化。

## 6. 过度工程化排除清单

上一节是既有权衡不翻案，这一节是没人要的能力不新建。审计过程里考虑过、明确不做的：WASM WebP 编码器、i18next、SSR、图层编辑器、
给所有滑杆加常驻输入、像素级撤销、Chromatic 一类外部视觉平台。判据统一：
现状有实测数字背书的不动，用户没诉求的能力不建，能用十行守住的不上平台。
