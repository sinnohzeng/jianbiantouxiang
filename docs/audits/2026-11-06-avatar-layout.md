# 圆裁头像产品评审与修复（2026-11-06）

## 方法与决定

从 Canvas 实际字形边界、生产合成管线的图片及真实显示尺寸开始，而不是据方案文字猜效果。评审方法和深化后的执行提示词保存在 `specs/v8.1-avatar-layout/review-method.md`。

- 修复文字量测：零及负的 actualBoundingBoxDescent 是有效值，不能被字体框下伸部替代。
- 自动字号面向圆裁安全区。每行真实矩形单独检查圆弧；Logo 和文字以紧凑整体居中，不把剩余空间塞到 Logo 与文字之间。
- 网页与自动化默认留白 6%。自动化取消原有 14.5% / 8% 小字号上限，主行最多 60%，副行最高为主行 62%，再以真实墨迹与圆形几何约束缩放。保留方形安全模式。
- 网页保留明确手动尺寸、补偿和旧存档边距。自动值与手动值含义清楚，不进行隐式旧存档重写。
- 增加 48 px 下墨迹高度不足 6 px 的建议提示；CLI/MCP 提供四档显示尺寸的实际行高。这个阈值是产品选择，不是飞书或 WCAG 官方可读性门槛。
- 实际界面截图发现默认中文字体在当前网络下失败，已改为随站点分发 Noto Sans SC 700；其他字体仍按原链路加载，OFL 许可证随产物提供。
- 不引入数据库、新服务或泛化布局框架。网页预览/导出共享 layoutText；自动化保留独立的单行字段契约和固定字体入口，复用圆形几何、渲染及编码。
- SVG/PNG 的字节、像素、资源引用限制及渲染隔离保留；没有为了默认效果关闭远程服务的沙箱或降低安全边界。

## 视觉证据

`node scripts/review-layout.mjs <输出目录>` 在运行中的 Vite 开发服务器上使用随包 Noto Sans SC 700 和实际合成模块，生成 12 组网页输出，逐组附方图、圆裁及 24/32/48/64 px 小图。包含 Logo/无 Logo、单行/双行、空首行、大小写、中英文长短文。测得图文整体几何中心误差小于 1e-12 px，圆形外可见前景像素数为 0（alpha > 16，包含文字效果）。这证明样例的几何与裁切，不等于证明所有文字都可读。

`node service/review.mjs <输出目录>` 生成 14 组自动化头像及小尺寸圆裁。相同原输入与 11-04 保存样张对比：

| 样例 | 原文字宽 | 新文字宽 | 增幅 |
| --- | ---: | ---: | ---: |
| 512 px，无 Logo 的“渐变头像 / Gradient Avatar” | 312.66 | 418.50 | 33.8% |
| 512 px，黑色透明 Logo + 产品研发 / Product Studio | 297.27 | 342.33 | 15.2% |
| 128 px，Logo + 研发 / STUDIO | 38.84 | 67.84 | 74.7% |

单 Logo 样例的高度由 287.54 增到 341.97 px。极宽/高 Logo 保持比例，不为填满而拉伸。长文本在 24/32 px 仍难辨认，已有缩短文本/删除副行的提示；没有声称自动排版可突破像素限制。尚未在真实飞书客户端中验收。

## 工程验证

- 818 项 Vitest 单测通过，包含圆裁角点、整体中心、极端比例/边距、旧默认显式保留与零下伸部。
- 3 项 HTTP 边界测试、6 组官方 SDK/CLI 集成测试通过。新增 circle 元数据及 CLI square 参数的两组实际渲染回归通过。
- lint、format:check、typecheck、静态站构建及 service 构建通过。
- 最终完整 Playwright 回归 48 项全部通过（含默认字体第三方网络阻断、重置默认值和小字提示）。桌面、iPhone 15、iPhone SE 深浅主题及导出状态共 16 张截图已检查。

本轮不发布远程 MCP。静态站发布通过功能分支/PR 完成，生产结果以 GitHub 与线上实际证据为准。旧 11-04 Docker 镜像不是本轮源码的构建产物。

依据：[MDN TextMetrics](https://developer.mozilla.org/en-US/docs/Web/API/TextMetrics/actualBoundingBoxLeft) 明确实际边界以 CSS 像素计量；[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 区分文字大小、抗锯齿与对比度。因此本项目不把单次背景抽样或固定像素阈值当成 WCAG 合规证明。
